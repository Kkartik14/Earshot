# Captured fixtures

`fixtures/captured` contains data used to check that Earshot can read real framework and
provider output. The directory has three kinds of fixtures:

- Incident bundles from LiveKit, Pipecat, Deepgram, Cartesia, and Sarvam. The root
  `manifest.json` lists each artifact, its adapter version, and the checks that were run.
  The bundles keep metadata and exclude transcript, identity, media, and raw OTLP payloads.
- Scripted end-to-end calls under `pipecat-otlp-1.5` and `livekit-otlp-1.8`. Tests replay
  the exported spans and recordings through Earshot. Both examples use the same fictional
  caller script and Cartesia-generated caller audio. The agent replies are generated by the
  model. Their manifests record capture provenance and the values intentionally retained.
- Scrubbed provider responses under `elevenlabs` and `twilio`. Their identifiers and phone
  numbers are replaced, and the manifests describe which audio was regenerated.

These checked-in samples contain no customer call. Captures from customers, unscripted
conversations, and provider accounts must stay in the ignored `.earshot` area. Never add
credentials, real caller details, or unscripted audio to this directory. Run the relevant
scrubber before publishing a new provider response.

## Check the Incident bundles

```bash
pytest -q packages/sdk-python/tests/test_captured_fixtures.py

for artifact in fixtures/captured/*.incident.json; do
  earshot validate "$artifact"
done
```

The test checks each bundle's digest, adapter version, and metadata-only privacy profile.

## Refresh a scripted call fixture

Run the matching example with the documented dependency versions and the fixed caller
script. Save raw output under `.earshot`, then use the fixture builder to update the public
files and manifest. Review the diff to confirm that identifiers and environment values
were scrubbed and that only the scripted dialogue and generated audio remain. Run the
replay, analysis, and projection tests for that example before committing the fixture.

## Refresh a provider response

Keep the original provider response in `.earshot`. Run `scripts/scrub_provider_capture.py`
to replace private identifiers and regenerate audio where the manifest requires it. Read
the updated manifest and files, then run the provider fixture tests. Never include the
unscrubbed source response or credentials in Git.

OpenAI Realtime and finalized-delivery connectors currently have no retained real provider
capture. Their absence is listed in the root manifest. Synthetic tests do not replace
missing source evidence.
